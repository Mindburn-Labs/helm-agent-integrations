# Native OpenClaw plugin

This HELM-compatible plugin registers native tools, hooks and a Responses
provider through the published OpenClaw 2026.9.6 plugin SDK. It reuses the
executor core at `337f8f4` and the qualified worker transport boundary at
`c43eb189`. It creates no Agent, A2A server, device-auth flow or effect ledger.
Its npm target is `@mindburn/helm-openclaw`, licensed Apache-2.0.

## Runtime binding

One plugin runtime consumes one existing `openclaw` checkout in one named
executor slot. The session launcher uses the canonical `helm-executor` login
and checkout commands. The plugin reads status through the exported core
command dispatcher, never by reading credential or slot files. Each gateway
dispatch calls the core's `episodeToken`, checks that the original work,
episode, workspace and deadline still match, and sends that opaque bearer only
to the explicit HTTPS executor edge. Tokens are neither parsed nor retained
in OpenClaw auth profiles. Stopped, reset, reassigned and ambiguous sessions
fail closed. A new native session needs a new plugin runtime.

Admin-owned plugin configuration contains `executorHome`, `slot`,
`edgeOrigin`, `model`, `maxOutputTokens`, `contextWindow` and `grantedTools`.
Optional `observedNativeTools` names a narrow local tool surface;
`blockedNativeTools` adds local refusals. There is no key or token setting.
The edge is an HTTPS origin without `/v1`; the provider uses `/v1/responses`
and the same origin's `/mcp`. No endpoint or model is inferred from a framework
default. The configuration selects a route; active mandates and the gateway
still decide authority, input/output bounds and budget admission.

`before_model_resolve` binds the host's exact native session. The provider's
ephemeral episode alias prevents its session-less stream factory from
selecting another retained route. The actual SDK request uses the retained
model id. The published `configureAiTransportHost` port supplies guarded
fetch to the real Responses provider; a global-fetch patch is insufficient.
Async context separates concurrent streams. Model responses retain the worker
1 MiB cap, MCP responses 4 MiB and the episode 8 MiB cap. Responses use SSE,
bounded output, no store or provider-side tool/search fallback.

The contextVersion-2 tool factory exposes only the granted names and schemas
actually returned by gateway MCP. It rechecks the native
`assertInvocationCurrent` immediately before dispatch. Calls preserve the
canonical target and arguments; the plugin creates no effect idempotency key.
The gateway owns D8 replay and UNKNOWN reconciliation.

## Observations and enforcement

The local `before_tool_call` hook blocks broad raw shell, outbound browser,
push, merge, Linear and deployment tools, plus every tool outside the explicit
surface. Native tools that overlap gateway tool names are refused. Other
listed native tools are observed-only. Hooks can be modified or bypassed by
the host operator: gateway credential custody and the actual executor network
profile are the enforcement boundary.

Pre/post events go through core `observe` with client `openclaw`; the plugin
never impersonates Codex. Core `337f8f4` accepts that client for checkout but
refuses it for observation. The additive OpenClaw observation and external
verdict metadata contract remains a core/CP producer dependency. Until it
lands, no observation persistence or T98 PASS is claimed. A failed observation
does not make a local deny into an allow. Raw output, tokens, prompts and
transcripts are not added to the observation envelope.

D19 admission and D20 worst-case reserve/cap/settlement remain gateway-owned.
The SDK's zero cost display metadata grants no free model route. Native D6
steer/pause/resume remains unsupported as declared by the worker capability
profile; Cancel is never presented as a resumable pause.

## Build and qualify

The root coordinator runs the finite jobs. From the repository worktree:

```sh
npm ci --prefix executors/core --ignore-scripts
npm run build --prefix executors/core
npm ci --prefix plugins/openclaw --ignore-scripts --engine-strict
npm run build --prefix plugins/openclaw
npm run check --prefix plugins/openclaw
cd plugins/openclaw
npm pack --ignore-scripts
```

The initial plugin lockfile must be generated by the parent before `npm ci`.
Assembly copies the canonical compiled core and worker boundary into the
tarball, verifies their immutable source pins, and records source/output
digests. It requires no unpublished `@mindburn` dependency, runtime source
checkout, credential file or installer script in the published package.

Focused tests and native source qualification are separate from actual OCE
installation, signed artifact delivery and a governed PR through the real
executor edge. G0 QA requires the actual E1 API, edge, core observation
extension, installed OCE plugin/readback and T98/T103/T87. Public publication
requires the WS-B-owned FR-79 digest-bound leaf gate under D31. This source
does not edit that shared workflow or claim those gates passed.

The SDK API is experimental and pinned. Source references are
[native plugin entry](https://docs.openclaw.ai/plugins/sdk-overview),
[plugin manifest](https://docs.openclaw.ai/plugins/manifest) and
the installed `openclaw2026.9.6` declarations for tool contexts, hooks and
provider stream factories. OCE installer catalog acceptance remains a
separate host integration check.
